speed Performance
Enable Hardware Acceleration
Enables GPU hardware acceleration for the WebView2 renderer. May improve rendering performance but can cause visual glitches on some systems.
Enable GPU Shader Cache
Caches compiled GPU shaders to disk. Reduces GPU startup overhead on subsequent launches.
Use 128 MB V8 Heap
Increases the JavaScript engine memory limit from 64 MB to 128 MB. Useful if VRCNext runs sluggishly with large friend lists or many open tabs.
Use 2 Render Processes
Allows WebView2 to use up to 2 renderer processes instead of 1. Can help with stability but uses slightly more memory.
Animations and Transitions
Disables all animations and transitions in VRCNext. This can speed up opening dialogs and switching between them, and may also save a little bit of CPU costs.
Blur Filters
Disables blur filters on modals and overlays. Instead of a blurred background, a dark overlay (75%) is shown. Especially useful when GPU acceleration is disabled, as blur effects are CPU-intensive. It is recommended to disable Blur Filters when using the app without GPU acceleration.
A restart is required to apply performance changes.

speed Performance
Search Index Debounce Speed
Search Index Debounce determines how many milliseconds it takes until it starts searching the database or certain entries after your last key press. Default is 500ms which works fine for almost every user. If you have more than 1000 Friends, 500ms is perfect. If you have more than 2500 Friends, it is recommended to use 750ms.
Do not change this to a value below 500ms, especially when you have a large friends list, many groups, many saved avatars and worlds!
cached Image Cache
VRCNext caches avatar, world, and profile images locally for instant loading. Over time this can grow to several gigabytes. Set a limit and the oldest cached images will be removed automatically when it is reached (~2 GB per cleanup pass).

bolt Fast Fetch Cache
Fast Fetch Cache stores user profiles, worlds, groups, and avatars locally to improve load times. When enabled, VRCNext instantly shows cached content (descriptions, texts, images) while silently refreshing it in the background. When disabled, all data is freshly downloaded on every request with no cache stored or used.

cleaning_services Database Optimization
Danger Zone! This Database Optimization will delete certain things from the database.
It will delete all cached non-friended users from the whole database. This is mostly safe as it does not contain any important information. Time Spent and Meet Counts are still present on those profiles and will not be wiped.
It will also delete certain events in your Personal and Friends Timeline. In the Personal Timeline, all notifications and URL entries will be wiped. In the Friends Timeline, all "Online", "Offline", and "Status Change" entries, for example "Ask Me" > "Join Me", will be wiped.
Run the analysis first. After that, you will see what will be wiped. It is recommended to create a backup of your database in case you still need those entries. Your database is usually stored at:
C:\Users\USERNAME\AppData\Roaming\VRCNext

download Import data from VRCX
Imports your VRCX history into VRCNext: world time, friend time, instance joins, GPS events, online/offline, status and bio changes. Existing data is preserved and values are added on top. Select your VRCX.sqlite3 file to begin.
warning Experimental Feature

Importing the VRCX database will only add necessary information. This feature is highly experimental and some data may be missing. Instance information works differently in VRCN, so some images or other details might not appear.

If your VRCX database is very important to you, it is recommended to continue using VRCX, as the data will not be fully merged with the VRCN database.

Full instance data will not be available and some elements may not display correctly.

account_circle Accounts
Manage your VRChat accounts. The primary account uses the main database, secondary accounts each get their own database. Credentials are stored locally and encrypted.
warningExperimental Feature
Switching Accounts is an experimental feature. It creates a separate database for each secondary account so the main database is not overloaded with data. Things might not work correctly on secondary accounts, expect bugs here and there. Secondary accounts do not get auto-backups, only your main account does. Some settings might not work as intended.
